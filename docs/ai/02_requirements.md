# AI質問機能 要件定義書 (`02_requirements.md`)

## 1. 文書情報・目的

- **関連文書**: `docs/ai/01_request.md`（AI質問機能 追加要望書）
- **目的**: Express / TypeScript 製既存Webアプリケーションに実装する「AI質問機能」について、機能仕様・入力制約・画面状態・エラー要件・非機能要件を確定し、次工程（`03_design.md`）のインプットとする。
- **対象システム**: 既存Webアプリケーション（Express / TypeScript / EJS / Vanilla JS）
- **採用LLM**: Google Gemini（公式SDK `@google/genai` を利用）

---

## 2. 利用者・ユースケース

### 2.1. 対象ユーザー
- 本Webアプリケーションを利用する一般ユーザーおよび管理者（既存アプリと同等のアクセス権限範囲）。

### 2.2. 基本ユースケース
1. ユーザーはナビゲーションまたは直接アクセス（`/ai`）によりAI質問画面を開く。
2. ユーザーは質問入力フォームに任意の質問テキストを入力し、送信操作を行う。
3. システムは入力値を検証したうえでバックエンド経由で Gemini API に問い合わせを行い、生成された回答を画面上に表示する。
4. ユーザーは回答を確認後、続けて別の質問を入力・送信できる。

---

## 3. 機能要件

### 3.1. 画面表示機能（`GET /ai`）
- 質問入力フォーム（テキストエリア・送信ボタン）、文字数カウンター、回答表示エリア、エラー表示エリアを備えたAI質問画面を表示すること。
- 既存の画面デザイン・共通レイアウト（ヘッダー・フッター・ナビゲーション等）と違和感のないUIとすること。

### 3.2. 質問送信・AI応答機能（`POST /ai/ask`）
- フロントエンドから非同期通信（`fetch`）で質問テキストをJSON形式で送信し、画面リロードなしで回答を取得・表示すること。
- バックエンド（Express）は受け取った質問テキストをバリデーションしたうえで `aiService` を経由して Gemini API を呼び出し、回答テキストをJSON形式で返却すること。
- 改行を含む回答テキストは、改行や段落が視認しやすい形式で画面に描画すること（XSS対策のため、原則テキストノードまたは適切なエスケープ処理を行って描画する）。

### 3.3. 入力制約・バリデーション要件

フロントエンド（UX向上目的）およびバックエンド（セキュリティ・整合性担保目的）の双方で以下の制約を適用する。

| 項目 | 制約内容 | 補足・備考 |
| :--- | :--- | :--- |
| **必須チェック** | 必須（未指定・`null`・`undefined` 不可） | `question` フィールドが存在すること |
| **型チェック** | 文字列型（`string`）のみ許可 | 数値・配列・オブジェクト等は `400` エラーとする |
| **空白のみ入力** | 禁止（前後の半角・全角スペース、改行を除去した状態で1文字以上必要） | `trim()` 後に空文字となる場合は未入力扱いとする |
| **最小文字数** | 1文字以上（`trim()` 後） | - |
| **最大文字数** | **1,000文字以内** | 改行も1文字としてカウント。超過時は送信不可／`400` エラー |
| **連続送信制御** | AI応答待ち（ローディング中）は再送信不可 | 送信ボタンの無効化およびフロントエンド側フラグで二重送信を防止 |

## 4. 画面状態遷移要件

AI質問画面は以下の4つの状態を持ち、ユーザー操作および通信結果に応じて排他的または明確に遷移すること。

| 状態名 | トリガー | UIの振る舞い・表示内容 |
| :--- | :--- | :--- |
| **1. 初期状態（Idle）** | 画面初回表示時 | - 入力欄：空欄・入力可能<br>- 送信ボタン：有効（または未入力時は無効）<br>- ローディング表示：非表示<br>- エラー表示：非表示<br>- 回答エリア：初期ガイド文言を表示（または非表示） |
| **2. 送信中（Loading）** | 有効な質問を送信した直後 | - 入力欄：編集不可（`disabled` または `readonly`）<br>- 送信ボタン：無効化（`disabled`）し「回答生成中...」等を表示<br>- ローディング表示：スピナーまたは待機メッセージを表示<br>- エラー表示：前回のエラーをクリアして非表示 |
| **3. 回答表示（Success）** | サーバーから正常応答（`200 OK`）を受信 | - 入力欄：編集可能に復帰（質問文は保持、または次入力しやすい状態）<br>- 送信ボタン：有効化<br>- ローディング表示：非表示<br>- 回答エリア：取得したAI回答を表示 |
| **4. エラー表示（Error）** | 入力不正・APIエラー・通信障害発生時 | - 入力欄：編集可能に復帰（**入力済みの質問テキストは消去せず保持**）<br>- 送信ボタン：有効化（再試行可能）<br>- ローディング表示：非表示<br>- エラー表示：原因に応じたユーザーフレンドリーなエラーメッセージを表示 |

## 5. エラーハンドリング要件

### 5.1. エラー分類とレスポンス方針

システム内部のスタックトレースやAPIキー等の機密情報をクライアントへ露出させず、以下の区分に従って適切なHTTPステータスとメッセージを返却する。

| エラー区分 | 発生ケース例 | HTTPステータス | 画面表示メッセージ方針（例） |
| :--- | :--- | :---: | :--- |
| **入力値不正** | 空文字、空白のみ、1,000文字超過、不正なJSON形式 | `400 Bad Request` | 「質問を入力してください。」「質問は1,000文字以内で入力してください。」 |
| **設定・認証不備** | `AI_API_KEY` 未設定、APIキー無効・権限不足 | `500` または `503` | 「現在AI機能を利用できません。管理者にお問い合わせください。」 |
| **レート制限超過** | Gemini API のリクエスト上限（429）到達 | `429 Too Many Requests` | 「アクセスが集中しています。しばらく時間をおいて再度お試しください。」 |
| **外部APIタイムアウト・障害** | Gemini API 応答遅延（タイムアウト）、外部サーバー障害（5xx） | `502` / `504` | 「AIからの応答がタイムアウトしました。時間をおいて再度お試しください。」 |
| **ネットワーク切断** | ブラウザ〜Express間の通信断・オフライン | （クライアント検知） | 「通信エラーが発生しました。ネットワーク接続を確認してください。」 |
| **予期せぬサーバー例外** | 上記以外のランタイム例外 | `500 Internal Server Error` | 「システムエラーが発生しました。時間をおいて再度お試しください。」 |

### 5.2. サーバー側例外処理要件
- すべての非同期処理の例外を確実に捕捉し、未処理の Promise Rejection 等で Node.js プロセスがクラッシュしないこと。
- 想定外のエラーは既存のグローバルエラーハンドラー（`next(err)`）へ連携し、既存アプリと統一されたエラーログ出力・レスポンス形式を維持すること。

## 6. 非機能要件

### 6.1. アーキテクチャ・保守性
- 既存の `src/apps/todo/` と同一のレイヤー責務分離（`Router` / `Controller` / `Service`）を踏襲し、`src/apps/ai/` 配下に独立して配置すること。
- `aiService.ts` 内に Gemini SDK 呼び出し処理をカプセル化し、将来的なモデル変更（例: `gemini-2.5-flash` から別モデルへの切替）やシステムプロンプト調整が他レイヤーに影響しない構造とすること。

### 6.2. 性能・タイムアウト
- 外部AI API呼び出しには適切なタイムアウト（目安：**30秒**）を設定し、無応答によるコネクション滞留を防ぐこと。

### 6.3. セキュリティ
- **APIキー管理**: `AI_API_KEY` は `.env` および実行環境の環境変数から `dotenv` 経由で読み込み、ソースコードやクライアント側JS・HTMLへ一切出力しないこと。
- **XSS対策**: AIが生成した回答には任意の記号・HTMLタグ文字列が含まれる可能性があるため、フロントエンド描画時に `innerHTML` へ生挿入せず、`textContent` 等を用いて安全にエスケープ描画すること。

### 6.4. 既存機能への非干渉（回帰要件）
- 既存の TODO 機能（`/` または `/todo` 配下の画面表示・CRUD操作）、DB接続、静的ファイル配信、404ハンドリング、グローバルエラーハンドリングの動作を一切変更・破壊しないこと。

---

## 7. スコープ外事項（本フェーズでは対象外）

- 会話履歴のDB永続化およびマルチターン（文脈を保持した連続対話）機能
- ストリーミング応答（SSE / WebSocket による逐次表示）
- Markdown のリッチHTMLレンダリングやコードハイライト表示
- ユーザーごとの利用回数制限（クォータ管理）および管理画面からのプロンプト編集機能

---

## 8. 完了条件（受入基準）

1. `GET /ai` でAI質問画面が正常に表示されること。
2. 有効な質問を送信するとローディング表示を経て、Gemini からの回答が画面に表示されること。
3. 空文字・空白のみ・1,001文字以上の入力時に適切なエラーメッセージが表示され、入力内容が保持されること。
4. APIキー未設定や外部APIエラー時にサーバーがクラッシュせず、画面にエラーメッセージが表示されること。
5. 既存の TODO アプリの全機能が従来どおり正常動作すること。
