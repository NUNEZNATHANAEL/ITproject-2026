Markdown# AI質問機能 テスト仕様書 (`05_test_spec.md`)

## 1. 文書情報・目的

- **関連文書**:
  - `docs/ai/01_request.md`（AI質問機能 追加要望書）
  - `docs/ai/02_requirements.md`（AI質問機能 要件定義書）
  - `docs/ai/03_design.md`（AI質問機能 設計書）
  - `docs/ai/04_implementation.md`（AI質問機能 実装手順書）
- **目的**: AI質問機能（`GET /ai`、`POST /ai/ask`、UI状態遷移、エラーハンドリング）が要件定義書および設計書の基準を満たしているか検証するためのテストケース・実施手順を定める。また、既存TODO機能への非干渉（回帰確認）を含める。

---

## 2. テスト環境・前提条件

- **アプリケーション環境**: Node.js / TypeScript / Express サーバーが起動可能であること。
- **正常系テスト用環境変数**: 有効な `AI_API_KEY` が `.env` または実行環境にセットされていること。
- **異常系テスト用環境変数**:
  - `AI_API_KEY` を空文字または未設定にした状態（`AI_CONFIG_ERROR` 検証用）
  - 無効なAPIキーを設定した状態（認証エラー検証用）
- **クライアント**: ブラウザ（Chrome / Edge 等、開発者ツール使用）および API 検証ツール（`curl` 等）。

## 3. テストケース一覧

### 3.1. 画面表示・UI状態遷移（`GET /ai` / ブラウザ）

| TC-ID | テスト項目 | 事前条件・入力操作 | 期待される結果 |
| :--- | :--- | :--- | :--- |
| **UI-01** | 初期画面表示（Idle状態） | サーバー起動後、ブラウザで `/ai` にアクセス | ・`200 OK` で画面が表示される<br>・入力欄が空で操作可能、文字数カウンターが `0 / 1,000文字`<br>・送信ボタンが有効、ローディング・エラー・回答エリアが非表示 |
| **UI-02** | 文字数カウンターのリアルタイム更新 | 入力欄に文字列を入力・削除、および1,001文字以上を入力 | ・入力文字数に応じてカウンターが更新される<br>・1,001文字以上で超過表示（`.is-over`）になる |
| **UI-03** | 送信中状態（Loading状態）と二重送信防止 | 有効な質問を入力し送信ボタンをクリック（応答待ち中） | ・入力欄と送信ボタンが無効化され、ボタン文言が「回答生成中...」になる<br>・ローディング表示が出現し、前回エラーがクリアされる<br>・連打しても `POST /ai/ask` が多重送信されない |
| **UI-04** | 正常回答表示（Success状態）とXSS安全性 | 「`<script>alert(1)</script>` とは何ですか？」等、記号やHTMLタグを含む質問を送信 | ・ローディングが消え、回答エリアにAI回答が表示される<br>・回答内や質問内にHTMLタグが含まれてもスクリプトが実行されず、テキストとして安全に描画される |
| **UI-05** | 連続質問の実施 | 1回目の回答表示後、別の質問を入力して再送信 | ・2回目の送信中状態を経て、新しい回答に更新される |
| **UI-06** | 入力エラー時の入力内容保持（Error状態） | 空欄・空白のみ・1,001文字以上で送信、またはAPIエラー発生 | ・エラーメッセージが表示される<br>・入力済みの質問テキストが消去されず保持され、再編集・再送信が可能 |

### 3.2. API 正常系・入力バリデーション（`POST /ai/ask`）

| TC-ID | テスト項目 | リクエスト内容（`Content-Type: application/json`） | 期待されるHTTPステータス・レスポンス |
| :--- | :--- | :--- | :--- |
| **API-01** | 正常質問送信 | `{"question": "TypeScriptの型注釈の利点を簡潔に教えてください。"}` | ・ステータス `200`<br>・`{"answer": "..."}` の形式で空でない文字列が返却される |
| **API-02** | 境界値：ちょうど1,000文字 | `question` が1,000文字の文字列 | ・ステータス `200`<br>・`{"answer": "..."}` が返却される |
| **API-03** | 境界値：1,001文字超過 | `question` が1,001文字の文字列 | ・ステータス `400`<br>・`error.code === "INVALID_INPUT"`、ユーザー向けメッセージが返却される |
| **API-04** | 空文字 | `{"question": ""}` | ・ステータス `400`<br>・`error.code === "INVALID_INPUT"` |
| **API-05** | 半角/全角スペース・改行のみ | `{"question": "   \n \t  "}` | ・ステータス `400`<br>・`error.code === "INVALID_INPUT"` |
| **API-06** | フィールド欠落 | `{}` | ・ステータス `400`<br>・`error.code === "INVALID_INPUT"` |
| **API-07** | 非文字列型 | `{"question": 123}` または `{"question": null}` または `{"question": ["a"]}` | ・ステータス `400`<br>・`error.code === "INVALID_INPUT"` |
| **API-08** | 不正なJSONボディ | `{invalid-json` | ・ステータス `400`（サーバーがクラッシュせず応答すること） |

### 3.3. 外部APIエラー・例外ハンドリング・プロセス安定性

| TC-ID | テスト項目 | 事前条件・操作 | 期待される結果 |
| :--- | :--- | :--- | :--- |
| **ERR-01** | `AI_API_KEY` 未設定 | `AI_API_KEY` を未設定（または空）で起動し、`POST /ai/ask` を実行 | ・ステータス `500`、`error.code === "AI_CONFIG_ERROR"`<br>・APIキー値やスタックトレースがレスポンスに含まれない<br>・サーバープロセスが停止・クラッシュしない |
| **ERR-02** | APIキー不正・認証エラー | 不正な `AI_API_KEY` を設定し、`POST /ai/ask` を実行 | ・ステータス `500`、`error.code === "AI_CONFIG_ERROR"`（または `502`）<br>・画面にユーザー向けエラーメッセージが表示され、サーバーが継続稼働する |
| **ERR-03** | ネットワーク通信断（クライアント側） | サーバー停止中またはオフライン状態で画面から質問を送信 | ・フロントエンドで例外が捕捉され、画面に通信エラーメッセージが表示される<br>・入力テキストが保持される |
| **ERR-04** | エラー発生後のサーバー生存確認 | `ERR-01`〜`ERR-03` 実行後、正常な設定に戻して `GET /ai` および `POST /ai/ask` を実行 | ・サーバーがクラッシュしておらず、正常に画面表示・回答取得ができる |

### 3.4. 既存機能への非干渉（回帰テスト）

| TC-ID | テスト項目 | 操作内容 | 期待される結果 |
| :--- | :--- | :--- | :--- |
| **REG-01** | 既存TODO画面・APIの動作確認 | 既存のTODO画面表示、TODOの作成・更新・完了切替・削除を実施 | ・従来どおり正常動作し、エラーや画面崩れが発生しない |
| **REG-02** | 未定義パス（404）の挙動確認 | 存在しないURL（例: `/ai/not-found` や `/unknown-path`）へアクセス | ・既存の404ハンドラーが機能し、サーバーがクラッシュしない |
