## 2. リクエストはどこを通るか

クライアント（ブラウザ）からの操作がDBに到達し、画面に反映されるまでの処理フローは以下の通りとする。

1. **画面操作（UI / `app.js`）**: ユーザーがボタン押下やフォーム送信を行う。
2. **APIクライアント（`TodoApi`）**: `fetch` 等を用いてバックエンドのエンドポイントへHTTPリクエストを送信する。
3. **エントリポイント（`index.ts`）**: 受信したリクエストのパスプレフィックス（例: `/api/todos`）に基づき、TODO専用ルーターへ処理を委譲する。
4. **ルーティング・ハンドラ（`routes/todo.ts` 等）**: HTTPメソッドとパスに応じて処理を振り分け、入力値の検証を行う。
5. **DBアクセス層（Repository / DBクライアント）**: SQLクエリを実行し、データの取得・更新を行う。
6. **レスポンス返却**: 処理結果をJSON形式で返却し、`TodoApi` を経由して画面を再描画する。

*(※ 授業テキストで採用しているフレームワーク・レイヤー分割に合わせ、4〜5の間の経由層は調整する：要確認)*

## 4. APIの共通ルール

* **ベースURL**: `/api/todos`（要確認）
* **データ形式**: リクエストボディ・レスポンスボディともに `application/json`（`Content-Type: application/json`）を使用する。
* **文字コード**: UTF-8
* **日付フォーマット**: ISO 8601形式（例: `2026-11-17T14:00:00.000Z`）※DB・授業方針に合わせる（要確認）
* **共通HTTPステータスコード**:
  * `200 OK`: 取得・更新・削除の成功
  * `201 Created`: 新規登録の成功
  * `400 Bad Request`: リクエストパラメータ・ボディのバリデーションエラー
  * `404 Not Found`: 指定されたIDのTODOが存在しない
  * `500 Internal Server Error`: サーバー内部またはDBエラー
* **エラーレスポンス形式（統一フォーマット）**:
  ```json
  {
    "error": {
      "code": "ERROR_CODE",
      "message": "エラー内容の説明"
    }
  }
